# 图形界面

适用于桌面、网页和移动软件的界面设计与实现。先核对项目的交互习惯、设计系统与现有控件，再决定需要补充什么。

## 一、控件选用与预览

项目已有控件库时，直接使用能满足需求的控件，沿用组件接口、主题和交互习惯。优先通过已有变体、插槽和组合方式接入。标准控件的常规使用可以在实际页面验证。

需要自定义控件时，先建立可运行的组件预览面板，已有面板就扩展现有面板。先在面板中实现并展示控件，再将同一个实现接入正式页面。预览用固定示例输入，覆盖有代表性的变体、尺寸和交互状态。业务页面通过组件接口传入实际数据与行为。

预览面板默认经开发或单独的预览入口运行。是否随正式产品发布，由用户要求或项目的交付约定决定。交付时在任务回复里给出可用的地址、启动命令或打开步骤，让用户能单独查看和操作控件。已授权的开发照常推进。用户明确要求先审预览时，在接入正式页面前提供预览并等待确认。

## 二、界面设计与检查

先确定用户的主要任务及操作顺序，再安排页面层级、空间和反馈。沿用项目的字号、间距、颜色和控件规则。细调对齐、留白、密度和交互反馈，检查每个主要操作能否找到、能否理解当前状态，以及操作失败后能否继续。界面文字应服务于任务，状态与帮助放在用户需要的位置。

交付前运行界面并实际查看受影响的页面和控件。可以直接操作，也可以查看从运行界面取得的截图。检查同类元素是否对齐，边距和间距是否协调，文字和控件是否清晰，有没有截断、溢出或重叠。按改动范围查看实际使用的窗口尺寸、主题及正常、空、加载和错误状态。交互变化应使用相应的输入方式操作一遍，检查焦点和反馈。

发现问题后调整，并再次查看实际结果。构建成功或读过布局代码只能说明对应检查已完成。无法运行目标环境时，尽量用可用环境预览，并在交付中说明哪些界面或交互还未目检。验证与交付记录见[验证与交付](delivery.md)。
