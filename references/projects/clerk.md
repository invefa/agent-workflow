# Clerk 命令行设计案例

Clerk 是声明驱动的工作区管理工具。本案例以提交 `884e171` 为基准，对照终端文档、CLI 实现和集成测试整理。通用做法见[命令行工具](../../standards/cli.md)。

| 做法 | 项目中的实现 |
|---|---|
| 参数按用途分层 | `--data-scope` 决定查哪些记录，过滤与排序处理查询结果，`--full` 决定正文详略，`--overflow` 决定终端怎样展示。 |
| 简写服务于手工输入 | 命令、动词和有固定候选的取值接受唯一前缀，完整名称优先。脚本和持久配置使用完整写法。长选项名本身要求完整。 |
| 一份命令定义支撑多个入口 | 上下文帮助、补全和机器可读的命令描述读取命令元数据，帮助只列当前命令适用的参数。 |
| 显式撤销配置默认 | `--no <option>` 可关闭或清除当前命令允许撤销的选项，并阻止该选项被配置回填。撤销只影响本次调用。 |
| 数据结果与终端显示分离 | 表格与 JSON 等格式从同一业务结果渲染。机器输出保留结构，分页与颜色属于终端展示。 |
| 关键边界有行为验证 | 集成测试覆盖帮助只读、解析与补全一致、歧义及无效参数、写入前校验、机器输出保持干净。 |

选项字母、前缀解析范围、JSON 信封、分页策略和退出码的细分取决于该项目的命令契约。可按目标工具的交互规模和兼容承诺取用。

来源见[终端设计](https://github.com/invefa/Clerk/blob/884e171d6488a0e57f0be1043a99716ca645c659/docs/features/terminal.md)、[CLI 实现](https://github.com/invefa/Clerk/blob/884e171d6488a0e57f0be1043a99716ca645c659/src/interface/cli.rs)和[集成测试](https://github.com/invefa/Clerk/blob/884e171d6488a0e57f0be1043a99716ca645c659/tests/cli.rs)。
