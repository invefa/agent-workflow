# Agent Note: 用 GraphQL 网关聚合内部接口

Status: rejected — 客户端只有两个消费者，引入 schema 与代码生成的维护成本高于它省掉的请求次数。

## Problem

桌面客户端需要为一次会话详情页请求会话、消息、附件、工作区四类数据，目前发四个 REST 请求，首屏因此有四次串行往返。考虑引入 GraphQL 网关，让客户端一次拿到所需字段。

## Proposal

在 API 层前加一个 GraphQL schema，把四类资源映射为类型，客户端按需查询。网关负责拆解查询、并行调用底层接口、按字段裁剪响应。

## Alternatives considered

**为详情页加一个聚合 REST 端点。** 实现约 200 行，客户端改动局限在一个调用点。缺点是聚合视图随页面变化需要改服务端。

**客户端并行发四个请求。** 不改服务端，四次串行变并行后首屏从 640ms 降到约 210ms，已满足目标。缺点是无法减少传输体积。

**引入 GraphQL。** 首屏能降到一次往返并裁剪字段，但要维护 schema、代码生成、权限映射和查询复杂度限制，且现有四个接口的字段语义并不完全一致（附件的权限模型独立于会话）。
